# Dev mode: единая тестовая БД

В локальном Docker PostgreSQL используется отдельная БД `hirerank_dev` (настройка `POSTGRES_DEV_DB`). Основная БД не содержит примеров из dev mode. `DEV_DATABASE_ENABLED=true` включается в `compose.override.yml`; в базовом compose выключен. Дополнительно сервер требует `ENVIRONMENT=local`. Имя dev БД не может совпадать с основной или системной БД.

Пользователи, вакансии, кандидаты, этапы и назначения используют обычные SQLModel-модели приложения и **ту же цепочку Alembic**, включая FK, ограничения и RLS. Настройки предпросмотра Copilot находятся в `development_dataset`; это также мигрируемая таблица, пустая в основной БД. Примеры определены только в серверном `backend/app/dev/fixtures.json`. Пароли и JWT в тестовом наборе отсутствуют: тестовые пользователи не являются учётными записями для входа.

## Создание и синхронизация

При запуске `prestart` обновляет основную БД, затем создаёт dev БД, применяет к ней `alembic upgrade head` и обновляет примеры через обычные ORM-модели. Повторное выполнение не создаёт дубликатов: идентификаторы стабильны. После изменения моделей сначала создайте миграцию Alembic и обновите генератор/fixtures для новых обязательных полей, затем выполните:

```sh
docker compose run --rm prestart
```

Для отдельного обновления dev БД:

```sh
docker compose exec backend python -m app.dev.bootstrap
```

Это синхронизирует схему и обновляет примеры. Интеграционная проверка в автоматически удаляемой временной БД: `docker compose run --rm --no-deps -v "$PWD/backend/tests:/app/backend/tests:ro" backend python -m scripts.verify_dev_database`. Генератор не может придумывать смысл нового обязательного поля, поэтому изменение модели требует соответствующего изменения генератора. Ошибка схемы останавливает запуск; endpoint проверяет Alembic head и возвращает 503 при несовпадении, а не выдаёт устаревший набор.

## Доступ и отображение

Единственный endpoint: `GET /api/v1/developer/dataset`. Существующая JWT/cookie-сессия проверяется обычным механизмом авторизации, затем активная роль из **основной** БД проверяется на `superuser`. Administrator может администрировать основное приложение, но не читать dev БД; остальные роли также получают 403. Без действующей сессии доступ закрыт. Endpoint ничего не записывает и не возвращает пароли, токены или хеши. Ответ помечен `Cache-Control: no-store, private`. Обычные бизнес-endpoints всегда используют основную БД. Для dev БД отозван `CONNECT` у `PUBLIC`; инфраструктурный владелец PostgreSQL сохраняет административный доступ.

Superuser включает Dev mode в боковой панели и выбирает роль предпросмотра. Все роли смотрят на **один набор**; различаются только разрешённые операции и видимость записей согласно роли. Переключение роли не создаёт и не загружает другой набор. Существующий UI получает адаптированное представление ORM-записей; алиасы идентификаторов используются только в предпросмотре.

Данные находятся в PostgreSQL и загружаются в оперативную память страницы для отображения. Пробные изменения и симуляция Copilot/MCP действуют до перезагрузки и не записываются ни в PostgreSQL, ни в localStorage/sessionStorage/IndexedDB. Это предпросмотр интерфейса, а не полноценный backend Copilot. Старые ключи localStorage удаляются при запуске. Зашитые клиентские наборы вакансий, кандидатов и метрик удалены. При ошибке доступа/загрузки локальные примеры не подставляются.

## Регистрация

Публичная регистрация поддерживает `administrator`; `superuser` через неё получить нельзя. В форме осталось обязательное согласие на обработку данных аккаунта. Опциональные согласия на кадровый резерв и трансграничную передачу скрыты и по умолчанию **не предоставляются**. На входе действие «Войти» сопровождается явным текстом о согласии на сбор и обработку данных и ссылками на документы.
